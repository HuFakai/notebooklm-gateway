从零部署 ​

本教程假设服务器已经安装 Git、Docker Engine 和 Docker Compose 插件。部署流程是：克隆源码、复制环境变量、构建镜像、启动容器、检查服务。

1. 克隆项目 ​

进入你希望保存项目的目录：

bash
cd /opt
git clone https://github.com/HuFakai/notebooklm-gateway.git
cd notebooklm-gateway

确认处于 main 分支：

bash
git branch --show-current
git log -1 --oneline

第一个命令应输出 main。

2. 创建环境配置 ​

bash
cp .env.example .env

默认配置可以直接启动：

dotenv
GATEWAY_PORT=18388
GATEWAY_ADMIN_TOKEN=notebooklm-gateway-default-token
GATEWAY_CORS_ORIGINS=
GATEWAY_MAX_CLIENTS=20
GATEWAY_CLIENT_IDLE_SECONDS=1800
GATEWAY_KEEPALIVE_SECONDS=600
GATEWAY_MAX_UPLOAD_BYTES=104857600

默认 GATEWAY_ADMIN_TOKEN 是：

text
notebooklm-gateway-default-token

它正好是 32 字节，可用于首次登录管理控制台和桌面凭据助手。任何知道默认值的人都能尝试访问管理接口，因此公网服务建议修改：

bash
nano .env

自定义值至少需要 32 字节。建议只使用字母、数字、连字符和下划线。如果 Token 包含 $，必须使用单引号，避免 Compose 把 $m9Xp 之类的内容当成环境变量：

dotenv
GATEWAY_ADMIN_TOKEN='包含$符号的自定义Token必须这样写'

修改 Token 后如何生效 ​

Compose 只在创建容器时注入环境变量。修改 .env 后不能只执行 docker compose restart，必须重新创建网关容器：

bash
docker compose up -d --no-deps --force-recreate gateway

镜像不需要重新构建。重新打开 /admin，使用新 Token 登录；桌面凭据助手中也要改成相同值。

3. 构建 Docker 镜像 ​

在包含 Dockerfile 的项目根目录执行：

bash
docker build -t notebooklm-gateway:latest . && \
  docker compose up -d --no-build

&& 很重要：只有构建成功才会执行启动命令。Compose 已配置 pull_policy: never，只使用刚刚在服务器构建的 notebooklm-gateway:latest，不会尝试从 Docker Hub 拉取同名项目镜像。

构建过程会在镜像内创建 /app/data。Compose 启动时还会自动创建名为 notebooklm-gateway-data 的 Docker 数据卷并挂载到该目录，因此无需手动创建目录或修改权限。

查看镜像：

bash
docker image ls notebooklm-gateway

4. 确认启动结果 ​

上一步已经启动服务。先确认本地镜像存在，再查看容器状态：

bash
docker image inspect notebooklm-gateway:latest >/dev/null
docker compose ps

正常情况下 notebooklm-gateway-server 先显示 starting，随后变成 healthy。

5. 验证服务 ​

bash
curl --fail http://127.0.0.1:18388/healthz

成功响应：

json
{"status":"ok"}

浏览器访问：

  • NoteWeb：http://<服务器IP>:18388/noteweb/
  • 管理控制台：http://<服务器IP>:18388/admin
  • 交互式 API：http://<服务器IP>:18388/docs

如果配置了 Nginx、Caddy 或 Cloudflare，请先确认服务器本机的健康检查成功，再检查反向代理是否指向 127.0.0.1:18388。

6. 添加 NotebookLM 账户 ​

在有桌面环境的电脑上运行凭据助手：

bash
git clone https://github.com/HuFakai/notebooklm-gateway.git
cd notebooklm-gateway
python3 -m venv .venv-client
PIP_CONFIG_FILE=/dev/null PIP_INDEX_URL=https://pypi.org/simple \
  .venv-client/bin/python -m pip install -e '.[client]'
.venv-client/bin/python gateway_client/app.py

如果 macOS 提示找不到 python 或 pip 证书错误，请按桌面凭据助手中的独立教程处理。

填写：

  1. 网关地址，例如 https://note.example.com。
  2. .env 中的 GATEWAY_ADMIN_TOKEN。
  3. Google 账户邮箱。
  4. 为该账户分配的用户 API Key。

完成浏览器登录并上传凭据后，即可使用用户 API Key 登录 NoteWeb。

7. 502 与容器启动失败排查 ​

Cloudflare 显示 502 Bad gateway 通常表示源站服务没有正常监听。先在服务器执行：

bash
docker compose ps
docker compose logs --tail=200 gateway
curl -v http://127.0.0.1:18388/healthz

日志提示 GATEWAY_ADMIN_TOKEN must contain at least 32 bytes ​

编辑 .env，使用默认值或自己的 32 字节以上 Token：

dotenv
GATEWAY_ADMIN_TOKEN=notebooklm-gateway-default-token

然后重新创建容器：

bash
docker compose up -d --no-deps --force-recreate gateway
docker compose logs --tail=100 gateway

构建提示 failed to resolve source metadata 或 Docker Hub 500 ​

这表示 Docker 在读取基础镜像 python:3.11-slim 时无法访问 Docker Hub，项目镜像尚未开始构建。先单独测试：

bash
docker pull python:3.11-slim

如果仍然返回 registry-1.docker.io 的 500 Internal Server Error，请稍后重试并检查服务器到 Docker Hub 的网络、DNS、代理或镜像加速配置。不要继续执行 docker compose up。

服务器已经配置可信的私有镜像仓库或加速地址时，可以覆盖基础镜像地址：

bash
docker build \
  --build-arg PYTHON_IMAGE=<可信镜像仓库>/library/python:3.11-slim \
  -t notebooklm-gateway:latest . && \
  docker compose up -d --no-build

把 <可信镜像仓库> 替换为你实际配置并信任的地址，不要原样执行。也可以按照 Docker 官方文档在 /etc/docker/daemon.json 中配置 registry-mirrors，重启 Docker 后再拉取。

出现 The "m9Xp" variable is not set ​

这不是名为 m9Xp 的必需配置，而是 .env 某个值含有 $m9Xp，Compose 尝试进行变量插值。最简单的修复是使用默认 Token：

dotenv
GATEWAY_ADMIN_TOKEN=notebooklm-gateway-default-token

如果必须保留带 $ 的 Token，请使用单引号包住完整值，然后重新创建容器。

本机健康检查成功，但域名仍然 502 ​

说明容器正常，问题位于反向代理或防火墙。确认：

  • Nginx/Caddy 上游地址是 http://127.0.0.1:18388。
  • GATEWAY_PORT 与反向代理端口一致。
  • Cloudflare DNS 指向当前服务器。
  • 反向代理配置修改后已经重新加载。

8. 数据卷与常用命令 ​

查看自动创建的数据卷：

bash
docker volume inspect notebooklm-gateway-data

SQLite 的 API Key 和 NotebookLM Cookie Storage State 是明文，应把该卷当作敏感数据管理。

bash
# 状态
docker compose ps

# 持续查看日志，Ctrl+C 退出
docker compose logs -f gateway

# 重启进程，不重新读取 .env
docker compose restart gateway

# 修改 .env 后重新创建容器
docker compose up -d --no-deps --force-recreate gateway

# 停止并删除容器，保留命名卷
docker compose down

# 再次启动
docker compose up -d --no-build

除非确定不再需要账户和生成任务，否则不要执行 docker compose down -v 或删除 notebooklm-gateway-data 数据卷。
