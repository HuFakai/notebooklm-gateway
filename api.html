NotebookLM Gateway REST API ​

本文对应网关 0.3.0 和 notebooklm-py==0.7.3，覆盖项目当前提供的全部 HTTP 接口。运行服务后，/docs 还会提供由实际 Pydantic Schema 生成的交互式 OpenAPI。

约定 ​

Base URL 示例：http://localhost:18388。

除 /healthz、静态页面和 OpenAPI 外，所有接口使用：

http
Authorization: Bearer <TOKEN>

Token 分为两类，不能混用：

类型可访问范围
管理 TokenPOST /v1/auth/credentials、/admin/api/*
用户 API KeyGET /v1/server/info、/v1/notebooks/*

管理 Token 调用业务 API 返回 403；无效、缺失或停用的用户 Key 返回 401。

普通 JSON 错误格式为：

json
{"detail": "error message"}

上游 SDK 错误另有 "upstream": true。常见状态码：400 参数错误、401/403 认证错误、404 不存在、409 冲突、413 文件过大、422 Schema 校验失败、429 上游限流、502 上游错误、504 等待超时。

所有 JSON 请求都应发送 Content-Type: application/json。路径中的 notebook_id、source_id、note_id、artifact_id、task_id 和 run_id 均为 NotebookLM 或本网关返回的字符串 ID，不应自行拼接。返回对象由网关把 notebooklm-py 的公开数据类转换成 JSON；日期输出 ISO 8601 字符串，枚举输出字符串，来源和生成物另外包含便于前端使用的 type、status 与 status_code。

管理和账户 ​

上传或刷新凭据 ​

POST /v1/auth/credentials，使用管理 Token。

json
{
  "email": "user@example.com",
  "api_key": "unique-user-api-key",
  "storage_state": "{\"cookies\":[...],\"origins\":[]}"
}
  • api_key：16–256 字符，不能含空白；不同账户必须唯一。
  • storage_state：JSON 字符串，顶层必须是对象且包含 cookies 数组。
  • 同一邮箱再次上传会更新凭据、使旧 SDK 客户端失效，并把账户状态恢复为 active。
  • api_key 与 storage_state 会直接写入 SQLite 明文字段。本项目将存储层作为二次开发基础，不内置字段加密；部署者必须限制 data/ 的访问权限。

成功响应：

json
{"ok":true,"account_id":1,"message":"Credentials updated"}

管理路由 ​

方法路径请求体/说明
GET/admin/api/accounts账户列表
DELETE/admin/api/accounts/{account_id}删除账户与其任务记录
PUT/admin/api/accounts/{account_id}/status`{"status":"active
PUT/admin/api/accounts/{account_id}/key{"api_key":"new-unique-key"}

管理控制台位于 /admin。

账户列表响应示例：

json
{
  "ok": true,
  "accounts": [
    {"id":1,"email":"user@example.com","api_key":"unique-user-api-key","status":"active","updated_at":"2026-07-14T10:00:00+00:00"}
  ]
}

状态只能是 active、disabled 或 expired。删除成功返回 {"ok":true}；修改状态成功返回 {"ok":true,"status":"active"}；修改 Key 成功返回 {"ok":true}。

系统信息 ​

GET /v1/server/info 返回网关版本、SDK 版本、当前账户和能力列表：

json
{
  "name": "notebooklm-gateway",
  "version": "0.3.0",
  "sdk_version": "0.7.3",
  "account": {"id": 1, "email": "user@example.com", "status": "active"},
  "capabilities": {
    "multi_tenant": true,
    "persistent_jobs": true,
    "artifact_types": ["audio", "video", "cinematic_video", "report", "quiz", "flashcards", "infographic", "slide_deck", "data_table", "mind_map"]
  }
}

GET /healthz 无需认证，成功返回 {"status":"ok"}。

方法路径请求体/响应
GET/v1/notebooks{"notebooks":[...]}
POST/v1/notebooks{"title":"标题"}，返回 201
GET/v1/notebooks/{notebook_id}获取详情
PATCH/v1/notebooks/{notebook_id}{"title":"新标题"}
DELETE/v1/notebooks/{notebook_id}返回 204

创建示例：

bash
curl -X POST "$BASE_URL/v1/notebooks" \
  -H "Authorization: Bearer $USER_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"title":"市场研究"}'

title 必须为 1–500 字符。列表固定使用 {"notebooks": [...]} 包装；详情、创建和重命名直接返回 SDK 的笔记本对象。删除成功没有响应体。

文件上传限制由 GATEWAY_MAX_UPLOAD_BYTES 控制，临时文件在成功或失败后都会删除。

来源请求字段：

字段约束
url4–8192 字符
title1–500 字符
text1–5,000,000 字符
urls1–50 个 URL
source_ids最多 100 个；等待接口传空数组表示等待全部来源
timeout大于 0 且不超过 1800 秒，默认 120
interval大于 0 且不超过 30 秒，默认 1

批量添加和等待接口都会返回 {"sources":[...],"errors":[...]}，其中单项失败不会让其他项停止。/text 与 /content 完全等价，响应中始终补充 text 字段。

对话 ​

提问 ​

POST /v1/notebooks/{notebook_id}/chat

json
{
  "question": "归纳三项关键结论",
  "source_ids": ["source-id"],
  "conversation_id": null
}

返回 SDK 的完整对话响应，包括回答、会话 ID 和引用信息。这是普通 JSON 响应，不是 SSE；NoteWeb 在客户端执行渐显效果。

question 为 1–20,000 字符；source_ids 省略时由上游决定使用范围；继续同一轮对话时传入上一响应的 conversation_id。

配置 ​

POST /v1/notebooks/{notebook_id}/chat/configure

使用预设模式：

json
{"chat_mode":"learning_guide"}

chat_mode 可选 default、learning_guide、concise、detailed。

或使用目标配置：

json
{
  "chat_mode": null,
  "goal": "custom",
  "response_length": "longer",
  "custom_prompt": "以资深研究员身份回答"
}

goal 可选 default、custom、learning_guide；response_length 可选 default、shorter、longer。

配置成功统一返回 {"ok":true}。当 chat_mode 非空时优先设置模式，其余三个字段不参与本次调用；要使用 goal、response_length 与 custom_prompt 时应省略 chat_mode。

深度研究 ​

方法路径说明
POST/v1/notebooks/{notebook_id}/research`{"query":"...","source":"web
GET/v1/notebooks/{notebook_id}/research/{run_id}查询进度和结果
POST/v1/notebooks/{notebook_id}/research/{run_id}/import导入结果来源；请求体可省略，也可传 {"sources":[...]}

query 长度为 1–10,000 字符。source 默认 web，mode 默认 fast。导入接口不传请求体时会先读取研究结果并导入全部候选来源；传入 {"sources":[...]} 时仅导入给定对象，成功返回 {"sources":[...]}。

Studio 生成物 ​

创建 ​

POST /v1/notebooks/{notebook_id}/artifacts，成功返回 202。公共参数：

json
{
  "type": "audio",
  "source_ids": ["source-id"],
  "language": "zh_Hans",
  "instructions": "面向初学者，先讲概念再讲案例"
}
  • type 必填。
  • source_ids 省略或为 null 时使用上游默认（通常为全部来源）。
  • language 默认 zh_Hans。NoteWeb 还提供 zh_Hant、en、ja、ko、es、fr、de。
  • instructions 最长 20,000 字符。

类型参数：

type专属字段可选值
audioaudio_formatdeep_dive、brief、critique、debate
audio_lengthshort、default、long
videovideo_formatexplainer、brief、cinematic
video_styleauto_select、custom、classic、whiteboard、kawaii、anime、watercolor、retro_print、heritage、paper_craft
style_prompt自定义视觉风格，最长 10,000 字符；video_style=custom 时使用
cinematic_video无使用公共参数
reportreport_formatbriefing_doc、study_guide、blog_post、custom
custom_prompt自定义报告结构
extra_instructions附加写作要求；未提供时回退到 instructions
quiz / flashcardsquantityfewer、standard、more
difficultyeasy、medium、hard
infographicorientationlandscape、portrait、square
detail_levelconcise、standard、detailed
infographic_styleauto_select、sketch_note、professional、bento_grid、editorial、instructional、bricks、clay、anime、kawaii、scientific
slide_deckslide_formatdetailed_deck、presenter_slides
slide_lengthdefault、short
data_table / mind_map无使用公共参数

完整示例：

json
{
  "type": "video",
  "source_ids": ["source-a", "source-b"],
  "language": "zh_Hans",
  "instructions": "制作五分钟产品说明",
  "video_format": "explainer",
  "video_style": "custom",
  "style_prompt": "深色编辑风格、蓝色数据可视化、克制的镜头运动"
}

查询与任务持久化 ​

方法路径说明
GET/v1/notebooks/{notebook_id}/artifacts上游生成物与本网关未完成任务的合并列表；同时返回 jobs
GET/v1/notebooks/{notebook_id}/artifacts/{task_id}轮询本网关登记的任务；跨账户、跨笔记本或未知任务返回 404
GET/v1/notebooks/{notebook_id}/artifacts/{artifact_id}/prompt返回创建时记录的指令和完整参数
PATCH/v1/notebooks/{notebook_id}/artifacts/{artifact_id}{"title":"新标题"}
POST/v1/notebooks/{notebook_id}/artifacts/{artifact_id}/retry重试有本网关任务记录的失败生成物，返回 202
DELETE/v1/notebooks/{notebook_id}/artifacts/{artifact_id}返回 204

任务记录写入 SQLite，因此进程重启不会丢失。prompt 返回的是本网关保存的创建参数，不调用上游私有 Prompt API。

创建通常返回：

json
{"task_id":"task-id","status":"pending","error":null}

轮询成功时在上游状态对象基础上补充 type。思维导图是同步生成，可能直接返回 completed。GET /artifacts 返回 {"artifacts":[...],"jobs":[...]}；尚未出现在上游列表中的本地任务也会合并到 artifacts。

下载 ​

POST /v1/notebooks/{notebook_id}/artifacts/download

{
  "type": "slide_deck",
  "artifact_id": "artifact-id",
  "output_format": "pptx"
}

artifact_id 必填，以避免误下载“最新”生成物。下载对应关系：

类型默认格式可选 output_format

cinematic_video 完成后在上游表现为视频生成物，下载时使用 type: "video"。

共享 ​

方法路径请求体/说明
GET/v1/notebooks/{notebook_id}/share当前公开状态、URL 与协作者
POST/v1/notebooks/{notebook_id}/share/public{"public":true}
POST/v1/notebooks/{notebook_id}/share/users`{"email":"a@example.com","permission":"viewer

新增协作者时 email 必须是合法邮箱；permission 默认 viewer，notify 默认 true，welcome_message 默认空字符串。路径中的邮箱必须进行 URL 编码。除删除接口返回 204 外，其余接口直接返回 SDK 的共享状态对象。

SDK 边界 ​

网关只导入 notebooklm 顶层公开对象和公开类型。SDK 升级必须先核对公开签名、更新 Schema 与本文档，并完成测试后再修改精确版本锁。研究取消返回 501 是当前稳定 SDK 能力边界，不代表请求仍在本网关后台执行；上游任务会自行继续。

接口清单核对 ​

本文覆盖健康检查、凭据上传、4 个账户管理接口、系统信息，以及笔记本、来源、对话、研究、笔记、Studio 和共享的全部路由。开发时应同时查看运行实例的 /openapi.json；新增或删除路由时必须同步更新本文和在线文档。
